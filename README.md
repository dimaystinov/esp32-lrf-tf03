# ESP32-C3-MINI-V1: LRF-HF → Benewake TF03

esp32lidar — проект `esp32-lrf-tf03`.

Текущая прошивка передаёт **TF03, 115200 8N1, 50 Гц**. **Симуляция выключена** (SIMULATE_DISTANCE=false). Передаются реальные показания LRF-HF после определения скорости UART. Если данные старше 250 мс, с ошибкой контрольной суммы, неполным кадром (таймаут 20 мс) или вне диапазона 5–5000 см, передаётся 0 см; спустя 2 секунды потери данных возобновляется поиск скорости.

- Выход GPIO10 → RX полётника, общий GND. GPIO3 — необязательный RX для диагностики входящих байтов, не подтверждение приёма.
- Лидар: TX → GPIO6, RX ← GPIO7 (команды не отправляются). [Подключение и питание](WIRING.md).
- Wi-Fi сразу после старта: **lidar_bridge**, пароль **00000000**, адрес **192.168.4.1**. Мощность 8,5 dBm.
- HTTP: `/`, `/api/status`, `/api/lidar`, `/api/fc`. Страница отдельно показывает симуляцию, реальные входные кадры и число пакетов, записанных в UART.
- `/api/fc`: `accepted=null`, `connected=null`, `ack_supported=false`. TF03 не подтверждает приём полётником; входящие байты не считаются ACK.

MAVLink полностью удалён из рабочей прошивки. [История MAVLink-моста](legacy/README.md).

## Сборка и прошивка

**Windows:** [пошаговая инструкция Arduino IDE и PowerShell](WINDOWS_FLASHING.md).


Установите Arduino CLI и Espressif ESP32 core 3.3.11. Выполнять из этой папки:

```sh
./build.sh c3
./flash.sh c3 /dev/cu.usbmodem101
```

Порт уточнить через `arduino-cli board list`. Локальный `firmware/lrf_hf_bridge/Secrets.h` исключён из Git; при переносе скопировать отдельно или заполнить по Secrets.example.h. Название каталога скетча сохранено для совместимости со скриптами.

[Формат TF03 и проверка обратной связи](TF03_TEST.md). Настройки полётника владелец меняет самостоятельно.

При запуске без лидара также передаётся 0. TF03 продолжает идти с частотой 50 Гц, при свежих допустимых данных возвращается реальная дальность. Нулевой кадр: `59 59 00 00 00 00 00 00 B2`. HTTP показывает distance_cm=0 и valid=false. При полном обрыве переход к нулю происходит через 250 мс после последнего измерения, на ближайшем цикле отправки (до 20 мс дополнительно).

На странице показаны **приём лидара (Гц)** и **отправка TF03 (Гц)**. Частоты вычисляются по приросту счётчиков за фактически прошедшее время, примерно раз в секунду. Приём считает кадры с корректной контрольной суммой (даже если расстояние вне диапазона); отправка — успешно записанные в UART пакеты, включая нулевые. Это не частота телеметрии Mission Planner и не подтверждение приёма полётником. API: `lidar.rate_hz`, `fc.tx_rate_hz`.
